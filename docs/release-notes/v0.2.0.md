## pi-image-view 0.2.0

Paste screenshots into Pi without pasting file paths.

### Install

```bash
pi install npm:pi-image-view
```

Reload an active Pi session with `/reload`, then paste with `Ctrl+V` (`Alt+V` on Windows and WSL).

Requires Pi `0.84.3`–`0.84.x`.

### Highlights

**Direct clipboard paste.** On macOS, Windows, and WSL the extension reads the image
clipboard itself, so `[Image #N]` appears the moment you paste — Pi never renders a
temporary `/var/folders/...` path. Reads are bounded and asynchronous, so the TUI does
not block while a subprocess runs. Native Linux keeps Pi's default editor and the burst
scan fallback.

**Atomic markers.** `←`/`→` jump across a whole `[Image #N]`, and `Backspace`/`Delete`
remove it in one undoable action.

**One-shot detail mode.** For a screenshot whose small text matters:

```text
/pi-image-view detail
```

The next image batch goes out at 1280px instead of 480px, then reverts automatically.

**Wider path support.** Windows drive and UNC paths, `~/`, `./`, and `../` — with
shell escapes resolved and relative paths anchored to the active Pi cwd. Drive paths
translate to `/mnt/<drive>/...` under WSL.

### Fixes

- A clipboard read that resolves after the draft was submitted no longer attaches its
  image to the following turn; overlapping pastes are serialized and a failed read is
  logged rather than ending the session.
- `~/My\ Photo.png` — a path dragged in from a file manager — now reads correctly.
- Non-PNG images are no longer sent through Kitty's PNG-only `f=100` transmission.
- Atomic whole-marker deletion is always undoable.
- On shutdown the extension restores the editor factory it displaced, and never clears
  one installed by another extension.
- `/pi-image-view clear` stays anchored across context compaction.

### Known limitations

- **`pi-zentui`:** load `pi-image-view` first so Zentui wraps its editor. The reverse
  order can destabilize editor/status reconciliation. Tracked in #1.
- One non-PNG image downgrades the whole draft gallery to text.
- Clipboard read timeouts have not been measured against a cold PowerShell start.
- Automatic blob deletion remains disabled; raw session exports still contain local
  `file://` history targets. Providers never receive those paths, but review session
  data before sharing it.
